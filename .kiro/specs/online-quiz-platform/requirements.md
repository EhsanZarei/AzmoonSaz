## ۱. چشم‌انداز و اهداف کلان

### ۱.۱ بیانیه چشم‌انداز

ساخت یک پلتفرم آزمون‌ساز آنلاین فارسی که **بهترین تجربه ممکن** را برای معلمان، مدرسان، سازمان‌ها و کسب‌وکارهای ایرانی فراهم کند؛ با ترکیب هوش مصنوعی، امنیت بالا، گیمیفیکیشن و رابط کاربری بومی‌سازی‌شده برای زبان فارسی.

### ۱.۲ اهداف استراتژیک

| هدف | شاخص موفقیت | بازه زمانی |
|-----|------------|-----------|
| تبدیل شدن به پلتفرم شماره یک آزمون‌ساز فارسی | ۱۰۰,۰۰۰ کاربر فعال | ۱۸ ماه |
| ارائه بهترین تجربه AI در ساخت آزمون | تولید آزمون از PDF در کمتر از ۶۰ ثانیه | ۶ ماه |
| پوشش کامل نیازهای آموزشی ایران | پشتیبانی از مدارس، دانشگاه‌ها، آموزشگاه‌ها | ۱۲ ماه |
| درآمد پایدار SaaS | MRR ۵۰۰ میلیون تومان | ۲۴ ماه |

### ۱.۳ مزیت رقابتی اصلی

- **AI بومی فارسی:** تولید سوال از متن، PDF، تصویر و ویدیو به زبان فارسی
- **گیمیفیکیشن کامل:** لیدربورد، نشان، امتیاز، مسابقه زنده
- **امنیت آزمون:** نظارت هوشمند بدون نیاز به نرم‌افزار جانبی
- **یکپارچگی بومی:** اتصال به درگاه‌های پرداخت ایرانی، پیامک، واتساپ، تلگرام
- **رابط کاربری RTL بومی:** طراحی از ابتدا برای فارسی، نه ترجمه

## ۲. بازار هدف و پرسوناهای کاربری

### ۲.۱ بازار هدف

**بازار اولیه (TAM):**
- ۱۵ میلیون دانش‌آموز و دانشجو در ایران
- ۱.۲ میلیون معلم و مدرس
- ۵۰۰,۰۰۰+ کسب‌وکار کوچک و متوسط
- ۱۰,۰۰۰+ آموزشگاه و موسسه آموزشی

**بازار ثانویه (SAM):**
- شرکت‌های بزرگ برای آموزش کارکنان (HR)
- سازمان‌های دولتی برای آزمون‌های استخدامی
- پلتفرم‌های آموزش آنلاین (LMS)

### ۲.۲ پرسوناهای کاربری

#### پرسونا ۱: معلم دبیرستان — «استاد احمدی»
- **سن:** ۳۵–۵۵ سال
- **نیاز اصلی:** ساخت سریع آزمون از کتاب درسی، نمره‌دهی خودکار
- **درد اصلی:** وقت‌گیر بودن تصحیح دستی، نگرانی از تقلب
- **انتظار:** رابط ساده، بدون نیاز به دانش فنی، گزارش نمرات
- **دستگاه:** موبایل و لپ‌تاپ

#### پرسونا ۲: مدرس آموزشگاه — «خانم رضایی»
- **سن:** ۲۵–۴۵ سال
- **نیاز اصلی:** آزمون‌های تعاملی، گیمیفیکیشن برای جذب دانش‌آموز
- **درد اصلی:** رقابت با پلتفرم‌های دیگر، نیاز به تمایز
- **انتظار:** قالب‌های زیبا، گواهینامه، لیدربورد
- **دستگاه:** لپ‌تاپ

#### پرسونا ۳: مدیر HR شرکت — «آقای کریمی»
- **سن:** ۳۰–۵۰ سال
- **نیاز اصلی:** آزمون استخدامی، ارزیابی عملکرد کارکنان
- **درد اصلی:** امنیت آزمون، گزارش‌دهی سازمانی، مدیریت تیم
- **انتظار:** SSO، API، گزارش Excel، برندینگ سازمانی
- **دستگاه:** لپ‌تاپ و دسکتاپ

#### پرسونا ۴: دانشجو — «علی»
- **سن:** ۱۸–۲۸ سال
- **نیاز اصلی:** تمرین و خودآزمایی، آمادگی برای کنکور
- **درد اصلی:** نبود محتوای تمرینی کافی به فارسی
- **انتظار:** رابط موبایل‌فرندلی، بازخورد فوری، گیمیفیکیشن
- **دستگاه:** موبایل (اندروید)

#### پرسونا ۵: استارتاپ آموزشی — «تیم EdTech»
- **سن:** ۲۵–۴۰ سال
- **نیاز اصلی:** API، White-label، یکپارچگی با LMS
- **درد اصلی:** نیاز به راه‌حل سریع بدون ساخت از صفر
- **انتظار:** API کامل، Webhook، مستندات فارسی
- **دستگاه:** همه دستگاه‌ها

## ۳. معماری کلان سیستم

### ۳.۱ رویکرد معماری

سیستم بر اساس **معماری Modular Monolith با قابلیت تبدیل به Microservices** طراحی می‌شود. این رویکرد برای تیم‌های کوچک در مرحله اولیه مناسب است و در صورت رشد، امکان جداسازی ماژول‌ها را فراهم می‌کند.

```
┌─────────────────────────────────────────────────────────┐
│                    Client Layer                          │
│  Web App (Next.js)  │  Mobile App (PWA)  │  API Clients │
└─────────────────────────────────────────────────────────┘
                           │
┌─────────────────────────────────────────────────────────┐
│                    API Gateway                           │
│         Rate Limiting │ Auth │ Load Balancing            │
└─────────────────────────────────────────────────────────┘
                           │
┌──────────┬──────────┬──────────┬──────────┬─────────────┐
│   Auth   │   Quiz   │   Exam   │  Report  │  AI Service │
│ Service  │ Builder  │ Delivery │ Service  │  (LLM API)  │
└──────────┴──────────┴──────────┴──────────┴─────────────┘
                           │
┌─────────────────────────────────────────────────────────┐
│                    Data Layer                            │
│  PostgreSQL  │  Redis (Cache)  │  S3 (Files)  │  ES     │
└─────────────────────────────────────────────────────────┘
```

### ۳.۲ Stack فناوری پیشنهادی

| لایه | فناوری | دلیل انتخاب |
|------|--------|------------|
| **Frontend** | Next.js 15 + TypeScript | SSR، SEO، عملکرد بالا |
| **Backend** | Node.js (NestJS) یا Go | مقیاس‌پذیری، سرعت |
| **Database** | PostgreSQL 16 | ACID، JSON support، قابل اعتماد |
| **Cache** | Redis 7 | Session، Rate Limit، Real-time |
| **File Storage** | MinIO (self-hosted) / S3 | ذخیره PDF، تصویر، ویدیو |
| **Search** | Elasticsearch | جستجوی سوالات بانک |
| **Queue** | BullMQ (Redis-based) | پردازش AI، ارسال ایمیل |
| **Real-time** | Socket.io | آزمون زنده، لیدربورد |
| **AI** | OpenAI API / Gemini / مدل بومی | تولید سوال |
| **CDN** | Cloudflare / ArvanCloud | سرعت در ایران |
| **Container** | Docker + Kubernetes | استقرار و مقیاس‌پذیری |

### ۳.۳ اصول طراحی سیستم

- **API-First:** همه عملکردها از طریق REST API قابل دسترس
- **Stateless:** سرورها بدون حالت، مناسب برای scale افقی
- **Event-Driven:** رویدادها از طریق Queue پردازش می‌شوند
- **Zero-Downtime Deployment:** استقرار بدون قطعی سرویس
- **Multi-Tenant:** پشتیبانی از چند سازمان روی یک نصب

- سیستم RBAC (Role-Based Access Control) با قابلیت تعریف نقش سفارشی
- هر سازمان می‌تواند نقش‌های اختصاصی تعریف کند
- مجوزها به صورت granular قابل تنظیم هستند
- لاگ کامل تمام عملیات حساس (Audit Log)

## ۵. ماژول احراز هویت و مدیریت حساب

### ۵.۱ روش‌های ورود

| روش | اولویت | توضیح |
|-----|--------|-------|
| شماره موبایل + OTP | 🔴 ضروری | پیامک از طریق ارائه‌دهندگان ایرانی |
| ایمیل + رمز عبور | 🔴 ضروری | با تأیید ایمیل |
| ورود با گوگل (OAuth) | 🟡 مهم | برای کاربران با VPN |
| ورود با GitHub | 🟢 اختیاری | برای توسعه‌دهندگان |
| SSO (SAML 2.0) | 🟡 مهم | برای سازمان‌های بزرگ |
| Magic Link | 🟢 اختیاری | ورود بدون رمز عبور |

### ۵.۲ امنیت احراز هویت

- **MFA (احراز هویت دو مرحله‌ای):** TOTP (Google Authenticator) + پیامک
- **JWT Token:** Access Token (15 دقیقه) + Refresh Token (30 روز)
- **Session Management:** مدیریت نشست‌های فعال، امکان خروج از همه دستگاه‌ها
- **Rate Limiting:** محدودیت تلاش ورود (۵ بار در ۱۵ دقیقه)
- **Password Policy:** حداقل ۸ کاراکتر، ترکیب حرف و عدد
- **Brute Force Protection:** قفل حساب پس از تلاش‌های ناموفق

### ۵.۳ مدیریت پروفایل

- نام، نام خانوادگی، شماره موبایل، ایمیل
- آواتار (آپلود تصویر یا انتخاب از پیش‌فرض)
- اطلاعات سازمانی (نام مدرسه/شرکت، سمت)
- تنظیمات اعلان (ایمیل، پیامک، درون‌برنامه‌ای)
- تاریخچه فعالیت
- مدیریت دستگاه‌های متصل

### ۵.۴ مدیریت سازمان

- ثبت سازمان با نام، لوگو، دامنه اختصاصی
- دعوت اعضا از طریق ایمیل یا لینک دعوت
- تأیید دستی یا خودکار اعضای جدید
- انتقال مالکیت سازمان
- حذف/تعلیق اعضا

## ۶. ماژول ساخت آزمون — انواع سوال

### ۶.۱ انواع سوال پشتیبانی‌شده

#### دسته اول: سوالات انتخابی

**۱. چهارگزینه‌ای (Multiple Choice — Single Answer)**
- حداقل ۲ و حداکثر ۸ گزینه
- نمایش عمودی یا افقی
- پشتیبانی از تصویر در گزینه‌ها
- تعریف نمره برای هر گزینه
- گزینه «هیچ‌کدام» و «همه موارد»

**۲. چندگزینه‌ای (Multiple Choice — Multiple Answer)**
- انتخاب چند گزینه صحیح
- نمره‌دهی جزئی (Partial Scoring)
- تعریف حداقل/حداکثر انتخاب

**۳. درست/غلط (True/False)**
- ساده‌ترین نوع سوال
- قابل تبدیل به بله/خیر، موافق/مخالف

**۴. بله/خیر (Yes/No)**
- برای نظرسنجی‌های سریع

#### دسته دوم: سوالات متنی

**۵. پاسخ کوتاه (Short Answer)**
- پاسخ یک تا چند کلمه
- مقایسه دقیق یا تقریبی (Fuzzy Match)
- پشتیبانی از Regex برای اعتبارسنجی

**۶. پاسخ تشریحی (Essay/Long Answer)**
- ویرایشگر متن غنی (Rich Text)
- محدودیت تعداد کلمه/کاراکتر
- نمره‌دهی دستی توسط مدرس
- پیشنهاد نمره توسط AI

**۷. پر کردن جای خالی (Fill in the Blank)**
- یک یا چند جای خالی در متن
- پاسخ‌های متعدد قابل قبول
- حساسیت به حروف بزرگ/کوچک قابل تنظیم

#### دسته سوم: سوالات تعاملی

**۸. جور کردن (Matching)**
- تطبیق ستون چپ با ستون راست
- قابل استفاده برای لغات، تعاریف، تصاویر

**۹. مرتب‌سازی (Ordering/Sequencing)**
- مرتب کردن آیتم‌ها با Drag & Drop
- مناسب برای توالی رویدادها، مراحل

**۱۰. کشیدن و رها کردن (Drag & Drop)**
- انداختن آیتم‌ها روی تصویر یا جدول
- مناسب برای نقشه، دیاگرام، آناتومی

**۱۱. نقطه‌گذاری روی تصویر (Hotspot)**
- کلیک روی ناحیه‌ای از تصویر
- تعریف مناطق صحیح با شکل‌های مختلف

**۱۲. طیف لیکرت (Likert Scale)**
- ۳، ۵ یا ۷ درجه
- برچسب‌های قابل سفارشی‌سازی
- مناسب برای نظرسنجی رضایت

**۱۳. امتیازدهی ستاره‌ای (Star Rating)**
- ۱ تا ۱۰ ستاره
- نمایش نیم‌ستاره

**۱۴. اسلایدر عددی (Numeric Slider)**
- بازه قابل تنظیم
- گام‌های دلخواه

#### دسته چهارم: سوالات رسانه‌ای

**۱۵. سوال با تصویر (Image Question)**
- تصویر در متن سوال یا گزینه‌ها
- پشتیبانی از JPG، PNG، WebP، SVG

**۱۶. سوال با ویدیو (Video Question)**
- آپلود ویدیو یا لینک YouTube/Aparat
- پخش ویدیو قبل از نمایش سوال

**۱۷. سوال با صدا (Audio Question)**
- آپلود فایل صوتی
- مناسب برای آزمون‌های زبان

**۱۸. آپلود فایل (File Upload)**
- دانش‌آموز فایل آپلود می‌کند
- محدودیت نوع و حجم فایل
- نمره‌دهی دستی

#### دسته پنجم: سوالات پیشرفته

**۱۹. ماتریسی (Matrix)**
- جدول سوال × گزینه
- هر ردیف یک سوال مستقل

**۲۰. رتبه‌بندی (Ranking)**
- مرتب کردن گزینه‌ها بر اساس اولویت

**۲۱. کد (Code Question)**
- ویرایشگر کد با Syntax Highlighting
- اجرای کد در Sandbox (اختیاری)
- مناسب برای آزمون‌های برنامه‌نویسی

**۲۲. فرمول ریاضی (Math Formula)**
- ویرایشگر LaTeX
- نمایش فرمول‌های ریاضی
- مناسب برای آزمون‌های فیزیک و ریاضی

**۲۳. نقشه ذهنی (Mind Map — اختیاری)**
- ترسیم نقشه ذهنی توسط دانش‌آموز

### ۶.۲ ویژگی‌های مشترک همه سوالات

- **توضیح سوال:** متن راهنما زیر سوال
- **بازخورد:** پیام بازخورد برای پاسخ صحیح/غلط
- **نمره:** تعریف نمره مثبت و منفی
- **اجباری/اختیاری:** تعیین الزامی بودن پاسخ
- **تگ‌گذاری:** دسته‌بندی سوال با تگ
- **سطح دشواری:** آسان، متوسط، سخت، خیلی سخت
- **زمان اختصاصی:** تایمر مجزا برای هر سوال
- **رسانه:** افزودن تصویر، ویدیو، صدا به هر سوال

## ۷. ماژول ساخت آزمون — تنظیمات پیشرفته

### ۷.۱ تنظیمات کلی آزمون

|-------|-------|---------|
| عنوان آزمون | نام نمایشی | — |
| توضیحات | متن معرفی آزمون | — |
| تصویر کاور | تصویر بنر آزمون | — |
| زبان | فارسی، انگلیسی، دوزبانه | فارسی |
| دسته‌بندی | موضوع آزمون | — |
| تگ‌ها | برچسب‌های جستجو | — |

### ۷.۲ تنظیمات زمانی

- **تایمر کل آزمون:** از ۱ دقیقه تا ۲۴ ساعت
- **تایمر هر سوال:** زمان مجزا برای هر سوال
- **تاریخ شروع/پایان:** زمان‌بندی خودکار
- **پنجره زمانی:** آزمون فقط در بازه مشخص قابل دسترس
- **نمایش تایمر:** نمایش/مخفی کردن تایمر برای شرکت‌کننده
- **هشدار زمان:** اعلان در ۵، ۱۰، ۳۰ دقیقه مانده

### ۷.۳ تنظیمات دسترسی

- **عمومی/خصوصی:** آزمون برای همه یا فقط دعوت‌شدگان
- **رمز عبور:** محافظت با کد دسترسی
- **محدودیت IP:** فقط از IP/رنج مشخص
- **محدودیت دستگاه:** فقط موبایل یا فقط دسکتاپ
- **تعداد شرکت‌کننده:** حداکثر تعداد مجاز
- **تعداد دفعات شرکت:** یک‌بار، چند بار، نامحدود
- **فاصله بین دفعات:** حداقل زمان بین دو شرکت

### ۷.۴ تنظیمات نمایش سوالات

- **ترتیب سوالات:** ثابت، تصادفی، بر اساس دشواری
- **ترتیب گزینه‌ها:** ثابت یا تصادفی
- **نمایش یک‌به‌یک:** هر سوال در صفحه جداگانه
- **نمایش همه:** همه سوالات در یک صفحه
- **بازگشت به سوال قبلی:** مجاز یا غیرمجاز
- **تعداد سوالات نمایشی:** انتخاب تصادفی از بانک
- **صفحه‌بندی:** تعداد سوال در هر صفحه

### ۷.۵ تنظیمات نمره‌دهی

- **نمره کل:** تعریف نمره ۱۰۰ یا سفارشی
- **نمره قبولی:** آستانه قبولی
- **نمره منفی:** کسر نمره برای پاسخ غلط
- **نمره جزئی:** نمره‌دهی بخشی برای سوالات چندگزینه‌ای
- **وزن‌دهی:** ضریب اهمیت هر سوال یا بخش
- **نمایش نمره:** بلافاصله، پس از پایان، دستی

### ۷.۶ تنظیمات بازخورد

- **نمایش پاسخ صحیح:** بلافاصله، پس از پایان، هرگز
- **نمایش توضیح:** نمایش راهنمای پاسخ
- **نمایش نمره هر سوال:** بله/خیر
- **پیام پایان:** متن سفارشی بر اساس نمره (قبول/رد)
- **هدایت پس از پایان:** URL دلخواه

### ۷.۷ منطق شرطی (Conditional Logic)

- **پرش سوال:** بر اساس پاسخ، سوال بعدی تغییر کند
- **نمایش/مخفی:** نمایش سوال بر اساس شرط
- **محاسبه متغیر:** تعریف متغیر و فرمول
- **صفحه نتیجه شرطی:** نمایش نتیجه متفاوت بر اساس امتیاز
- **شرط‌های ترکیبی:** AND/OR بین شرط‌ها

### ۷.۸ بخش‌بندی آزمون (Sections)

- تقسیم آزمون به بخش‌های مجزا
- تایمر مستقل برای هر بخش
- نمره مستقل برای هر بخش
- ترتیب تصادفی بخش‌ها
- توضیحات مجزا برای هر بخش

## ۱۰. ماژول برگزاری آزمون (Exam Delivery)

### ۱۰.۱ انواع حالت برگزاری

#### حالت ۱: آزمون آنلاین استاندارد
- شرکت‌کننده از طریق لینک وارد می‌شود
- پاسخ‌ها به صورت real-time ذخیره می‌شوند
- امکان ادامه پس از قطع اینترنت (Offline Mode)

#### حالت ۲: آزمون زنده (Live Quiz)
- مدرس آزمون را در لحظه کنترل می‌کند
- همه شرکت‌کنندگان سوال را همزمان می‌بینند
- لیدربورد زنده
- مناسب برای کلاس درس و رویداد

#### حالت ۳: آزمون خودآزمایی (Self-Paced)
- شرکت‌کننده هر زمان می‌تواند شروع کند
- بازخورد فوری بعد از هر سوال
- امکان مکث و ادامه

#### حالت ۴: آزمون تطبیقی (Adaptive)
- سطح سوالات بر اساس عملکرد تنظیم می‌شود
- الگوریتم IRT (Item Response Theory)
- مناسب برای ارزیابی دقیق سطح

### ۱۰.۲ تجربه شرکت‌کننده

**صفحه ورود به آزمون:**
- نمایش اطلاعات آزمون (عنوان، مدت، تعداد سوال)
- دستورالعمل‌های آزمون
- تأیید هویت (در صورت نیاز)
- تست سیستم (دوربین، میکروفون)

**حین آزمون:**
- نوار پیشرفت (Progress Bar)
- تایمر واضح
- علامت‌گذاری سوال برای بازگشت
- ذخیره خودکار هر ۳۰ ثانیه
- هشدار قبل از پایان زمان
- امکان مرور سوالات قبل از ارسال

**صفحه پایان:**
- خلاصه پاسخ‌ها
- نمره (در صورت تنظیم نمایش فوری)
- گواهینامه (در صورت قبولی)
- اشتراک‌گذاری نتیجه

### ۱۰.۳ مقاومت در برابر قطعی اینترنت

- ذخیره پاسخ‌ها در LocalStorage مرورگر
- همگام‌سازی خودکار پس از اتصال مجدد
- نمایش وضعیت اتصال به کاربر
- تایمر ادامه می‌یابد حتی در حالت آفلاین

### ۱۰.۴ پشتیبانی از دستگاه‌ها

| دستگاه | پشتیبانی | توضیح |
|--------|---------|-------|
| دسکتاپ (Chrome, Firefox, Edge) | ✅ کامل | همه ویژگی‌ها |
| موبایل اندروید | ✅ کامل | PWA + Responsive |
| موبایل iOS | ✅ کامل | PWA + Responsive |
| تبلت | ✅ کامل | طراحی تطبیقی |
| مرورگر Safari | ✅ | با محدودیت‌های جزئی |

### ۱۰.۵ مدیریت آزمون در حال برگزاری

- مشاهده لیست شرکت‌کنندگان آنلاین
- مشاهده پیشرفت هر شرکت‌کننده
- ارسال پیام به همه یا یک نفر
- تمدید زمان برای یک یا همه
- حذف شرکت‌کننده
- توقف/ادامه آزمون
- اضافه کردن زمان اضافه

## ۱۱. ماژول نظارت و پایش (Proctoring)

### ۱۱.۱ سطوح نظارت

| سطح | نام | توضیح | مناسب برای |
|-----|-----|-------|-----------|
| ۰ | بدون نظارت | هیچ محدودیتی | خودآزمایی |
| ۱ | نظارت پایه | ضبط IP، مرورگر، زمان | آزمون‌های کلاسی |
| ۲ | نظارت متوسط | قفل مرورگر + تشخیص تب | آزمون‌های مهم |
| ۳ | نظارت پیشرفته | دوربین + AI | آزمون‌های رسمی |
| ۴ | نظارت کامل | دوربین + صدا + صفحه | آزمون‌های حساس |

### ۱۱.۲ ویژگی‌های نظارت پایه (سطح ۱)

- ثبت IP و موقعیت جغرافیایی
- ثبت مرورگر و سیستم‌عامل
- ثبت زمان شروع، پایان، مکث‌ها
- تشخیص تغییر تب مرورگر
- تشخیص کپی/پیست متن
- ثبت تعداد دفعات خروج از صفحه

### ۱۱.۳ قفل مرورگر (Browser Lockdown — سطح ۲)

- غیرفعال کردن کلیدهای میانبر (Ctrl+C، Ctrl+V، F12)
- جلوگیری از باز کردن تب جدید
- جلوگیری از کلیک راست
- تشخیص تغییر پنجره (Window Blur)
- هشدار و ثبت هر تخلف
- پایان خودکار آزمون پس از N تخلف

### ۱۱.۴ نظارت با دوربین (AI Proctoring — سطح ۳ و ۴)

**تشخیص چهره:**
- تأیید هویت در شروع آزمون
- تشخیص غیبت از جلوی دوربین
- تشخیص حضور چند نفر
- تشخیص نگاه به کنار (Eye Tracking)

**تشخیص رفتار مشکوک:**
- صحبت کردن
- استفاده از گوشی
- نگاه به کاغذ
- حرکات غیرعادی

**ضبط و گزارش:**
- ضبط ویدیو در فواصل مشخص (Snapshot)
- ضبط مداوم (اختیاری)
- گزارش رویدادهای مشکوک با تایم‌استمپ
- بررسی دستی توسط مدرس

### ۱۱.۵ حریم خصوصی در نظارت

- اطلاع‌رسانی شفاف به شرکت‌کننده قبل از آزمون
- رضایت‌نامه دیجیتال
- ذخیره‌سازی رمزنگاری‌شده
- حذف خودکار پس از مدت مشخص
- دسترسی محدود به داده‌های نظارتی

## ۱۲. ماژول نمره‌دهی و ارزیابی

### ۱۲.۱ نمره‌دهی خودکار

**سوالات با نمره‌دهی خودکار:**
- چهارگزینه‌ای، درست/غلط، بله/خیر
- پر کردن جای خالی (مقایسه دقیق/تقریبی)
- جور کردن، مرتب‌سازی
- پاسخ کوتاه (با Regex یا لیست پاسخ‌های قابل قبول)

**الگوریتم نمره‌دهی:**
```
نمره سوال = (نمره پایه × ضریب سوال) - (نمره منفی × تعداد اشتباه)
نمره کل = Σ نمره سوالات / نمره کل × ۱۰۰
```

### ۱۲.۲ نمره‌دهی جزئی (Partial Scoring)

برای سوالات چندگزینه‌ای:
- روش ۱: نمره کامل فقط اگر همه گزینه‌های صحیح انتخاب شوند
- روش ۲: نمره متناسب با تعداد گزینه‌های صحیح انتخابی
- روش ۳: نمره منفی برای گزینه‌های غلط انتخابی

### ۱۲.۳ نمره‌دهی دستی

**صف نمره‌دهی:**
- لیست پاسخ‌های تشریحی در انتظار نمره
- نمایش پاسخ شرکت‌کننده و پاسخ نمونه
- پیشنهاد نمره توسط AI
- ثبت نظر/بازخورد برای هر پاسخ
- نمره‌دهی کور (Blind Grading) — مخفی کردن نام

**ابزارهای نمره‌دهی:**
- Rubric (معیار نمره‌دهی) قابل تعریف
- نمره‌دهی دسته‌جمعی (یک نمره برای همه)
- مقایسه پاسخ‌های مختلف کنار هم

### ۱۲.۴ تجدیدنظر در نمره

- درخواست تجدیدنظر توسط شرکت‌کننده
- بررسی و پاسخ توسط مدرس
- تاریخچه تغییرات نمره
- اعلان به شرکت‌کننده پس از تغییر

### ۱۲.۵ آمار نمره‌دهی

- میانگین، میانه، انحراف معیار
- توزیع نمرات (Histogram)
- بالاترین و پایین‌ترین نمره
- درصد قبولی
- آمار هر سوال (درصد پاسخ صحیح، زمان متوسط)
- شناسایی سوالات بد (سوالاتی که همه غلط پاسخ دادند)

## ۱۳. ماژول گزارش‌دهی و تحلیل

### ۱۳.۱ داشبورد مدرس

**نمای کلی:**
- تعداد آزمون‌های فعال
- تعداد شرکت‌کنندگان امروز/هفته/ماه
- میانگین نمره آخرین آزمون‌ها
- نمودار فعالیت (Activity Chart)

**گزارش هر آزمون:**
- لیست شرکت‌کنندگان با نمره و وضعیت
- نمودار توزیع نمرات
- آمار هر سوال
- زمان متوسط پاسخ به هر سوال
- نرخ تکمیل آزمون
- مقایسه با آزمون‌های قبلی

|-------|------|-------|

| گزارش پیشرفت | PDF | مقایسه چند آزمون |
| گزارش سازمانی | Excel، PDF | آمار کل سازمان |

### ۱۳.۳ تحلیل پیشرفته

**تحلیل سوال (Item Analysis):**
- ضریب دشواری (Difficulty Index)
- ضریب تمایز (Discrimination Index)
- تحلیل گزینه‌ها (Distractor Analysis)
- پیشنهاد حذف/بهبود سوالات ضعیف

**تحلیل یادگیری:**
- نقشه دانش (Knowledge Map) — کدام موضوعات ضعیف است
- پیشرفت در طول زمان
- مقایسه با میانگین گروه
- پیشنهاد مطالعه بیشتر

**تحلیل سازمانی:**
- مقایسه عملکرد گروه‌ها/کلاس‌ها
- روند پیشرفت سازمان
- شناسایی بهترین و ضعیف‌ترین حوزه‌ها

### ۱۳.۴ داشبورد دانش‌آموز

- نمرات آزمون‌های گذشته
- نمودار پیشرفت
- مقایسه با میانگین کلاس (بدون نام دیگران)

- پیشنهاد مطالعه

مدرس → ایجاد اتاق → کد اتاق → شرکت‌کنندگان وارد می‌شوند

**ویژگی‌های آزمون زنده:**

- لیدربورد بین هر سوال
- حالت تیمی (Team Mode)
- حالت بدون رقابت (Collaborative)

### ۱۵.۵ چالش و مسابقه

- **چالش دوستانه:** دعوت دوست به رقابت
- **مسابقه زمان‌دار:** آزمون با جایزه

- **تورنمنت:** مسابقه حذفی

## ۲۲. پشتیبانی از زبان فارسی و RTL

### ۲۲.۱ الزامات RTL

- **جهت متن:** راست به چپ برای فارسی، چپ به راست برای انگلیسی
- **چیدمان:** تمام عناصر UI در حالت RTL آینه می‌شوند
- **آیکون‌های جهت‌دار:** فلش‌ها و آیکون‌های ناوبری برعکس می‌شوند
- **Padding/Margin:** مقادیر start/end به جای left/right
- **Flexbox/Grid:** direction: rtl

### ۲۲.۲ پشتیبانی از تقویم شمسی

- نمایش تاریخ به شمسی در همه جا

## ۲۳. دسترس‌پذیری (Accessibility)

### ۲۳.۱ استاندارد WCAG 2.2 AA

سیستم باید با استاندارد **WCAG 2.2 سطح AA** مطابقت داشته باشد:

**اصل ۱ — قابل درک (Perceivable):**
- متن جایگزین برای همه تصاویر (alt text)
- زیرنویس برای ویدیوها
- نسبت کنتراست رنگ حداقل ۴.۵:۱
- متن قابل بزرگ‌نمایی تا ۲۰۰٪ بدون از دست دادن محتوا

**اصل ۲ — قابل استفاده (Operable):**
- همه عملکردها از طریق کیبورد قابل دسترس
- بدون محتوای چشمک‌زن (Seizure Prevention)
- عنوان صفحه توصیفی
- Focus Indicator واضح

**اصل ۳ — قابل فهم (Understandable):**
- زبان صفحه مشخص (`lang="fa"`)
- پیام‌های خطای واضح
- برچسب‌های فرم توصیفی

**اصل ۴ — قوی (Robust):**
- سازگاری با Screen Reader (NVDA، JAWS، VoiceOver)
- استفاده صحیح از ARIA attributes
- HTML معنایی (Semantic HTML)

### ۲۳.۲ پشتیبانی از ناتوانی‌های بینایی

- حالت کنتراست بالا (High Contrast Mode)
- پشتیبانی از Screen Reader
- توضیح صوتی برای نمودارها
- فونت بزرگ‌تر برای کم‌بینایان

### ۲۳.۳ پشتیبانی از ناتوانی‌های حرکتی

- ناوبری کامل با کیبورد (Tab، Enter، Space، Arrow Keys)
- دکمه‌های بزرگ (حداقل ۴۴×۴۴ پیکسل)
- بدون محدودیت زمانی برای تعاملات UI
- پشتیبانی از Switch Access

### ۲۳.۴ تنظیمات دسترس‌پذیری برای آزمون

- زمان اضافه برای افراد دارای معلولیت
- فونت بزرگ‌تر
- حالت خواندن با صدا (Text-to-Speech)
- کنتراست بالا
- غیرفعال کردن انیمیشن‌ها

## ۲۴. امنیت سیستم

### ۲۴.۱ امنیت احراز هویت

- **رمزنگاری رمز عبور:** bcrypt با salt (cost factor: 12)
- **JWT:** امضای RS256، انقضای کوتاه
- **Refresh Token Rotation:** هر بار استفاده، توکن جدید
- **Session Invalidation:** خروج از همه دستگاه‌ها
- **Account Lockout:** قفل پس از ۵ تلاش ناموفق
- **CAPTCHA:** برای ثبت‌نام و ورود مشکوک

### ۲۴.۲ امنیت داده

- **رمزنگاری در حال انتقال:** TLS 1.3
- **رمزنگاری در حال ذخیره:** AES-256 برای داده‌های حساس
- **رمزنگاری فایل‌ها:** فایل‌های آپلودشده رمزنگاری می‌شوند
- **Database Encryption:** رمزنگاری سطح دیتابیس
- **Backup Encryption:** پشتیبان‌گیری رمزنگاری‌شده

### ۲۴.۳ امنیت API

- **Rate Limiting:** محدودیت درخواست بر اساس IP و کاربر
- **Input Validation:** اعتبارسنجی همه ورودی‌ها
- **SQL Injection Prevention:** Parameterized Queries
- **XSS Prevention:** Content Security Policy + Output Encoding
- **CSRF Protection:** CSRF Token برای همه فرم‌ها
- **CORS:** تنظیم دقیق دامنه‌های مجاز
- **API Key Rotation:** امکان تجدید API Key

### ۲۴.۴ امنیت آزمون

- **یکتایی لینک:** هر شرکت‌کننده لینک منحصربه‌فرد دارد
- **محدودیت IP:** آزمون فقط از IP مشخص
- **تشخیص VPN/Proxy:** هشدار یا مسدودسازی
- **Watermark:** نام شرکت‌کننده روی صفحه آزمون
- **رمزنگاری سوالات:** سوالات در مرورگر رمزنگاری می‌شوند
- **جلوگیری از DevTools:** تشخیص باز بودن Developer Tools
- **Screenshot Prevention:** جلوگیری از اسکرین‌شات (محدود)

### ۲۴.۵ Audit Log

- ثبت همه عملیات حساس
- اطلاعات: کاربر، زمان، IP، عملیات، نتیجه
- نگهداری لاگ‌ها حداقل ۱ سال
- جستجو و فیلتر در لاگ‌ها
- هشدار برای فعالیت‌های مشکوک

### ۲۴.۶ تست امنیتی

- **OWASP Top 10:** بررسی و رفع همه آسیب‌پذیری‌های OWASP
- **Penetration Testing:** تست نفوذ قبل از راه‌اندازی
- **Dependency Scanning:** بررسی آسیب‌پذیری کتابخانه‌ها
- **SAST/DAST:** تحلیل استاتیک و داینامیک کد
- **Bug Bounty:** برنامه گزارش آسیب‌پذیری

## ۲۵. عملکرد و مقیاس‌پذیری

### ۲۵.۱ اهداف عملکردی

| معیار | هدف | اندازه‌گیری |
|-------|-----|------------|
| زمان بارگذاری صفحه اول | < ۲ ثانیه | LCP |
| زمان پاسخ API | < ۲۰۰ms (P95) | Latency |
| زمان تولید سوال AI | < ۶۰ ثانیه | End-to-end |
| Uptime | ۹۹.۹٪ | SLA |
| همزمانی آزمون زنده | ۱۰,۰۰۰ نفر | Load Test |
| ظرفیت کل | ۱۰۰,۰۰۰ کاربر همزمان | Stress Test |

### ۲۵.۲ استراتژی Caching

```
لایه ۱: Browser Cache
  - فایل‌های استاتیک: ۱ سال
  - صفحات HTML: بدون cache

لایه ۲: CDN Cache (Cloudflare/ArvanCloud)
  - تصاویر و فایل‌ها: ۳۰ روز
  - API responses عمومی: ۵ دقیقه

لایه ۳: Redis Cache
  - Session: ۳۰ روز
  - نتایج آزمون: ۱ ساعت
  - لیدربورد: ۳۰ ثانیه
  - تنظیمات سازمان: ۱ ساعت

لایه ۴: Database Query Cache
  - Query‌های پرتکرار: ۵ دقیقه
```

### ۲۵.۳ بهینه‌سازی دیتابیس

- **Indexing:** ایندکس روی فیلدهای پرجستجو
- **Connection Pooling:** PgBouncer
- **Read Replicas:** جداسازی خواندن و نوشتن
- **Partitioning:** تقسیم جداول بزرگ (submissions)
- **Archiving:** آرشیو داده‌های قدیمی

### ۲۵.۴ مقیاس‌پذیری افقی

- **Stateless Services:** همه سرویس‌ها بدون حالت
- **Auto Scaling:** افزایش خودکار سرور در زمان اوج
- **Load Balancing:** توزیع بار بین سرورها
- **Database Sharding:** در صورت نیاز به مقیاس بالا
- **Message Queue:** پردازش غیرهمزمان با BullMQ

### ۲۵.۵ بهینه‌سازی Frontend

- **Code Splitting:** بارگذاری تنبل (Lazy Loading)
- **Image Optimization:** WebP، فشرده‌سازی خودکار
- **Bundle Size:** حداکثر ۲۰۰KB برای First Load
- **Service Worker:** PWA و کش آفلاین
- **Prefetching:** پیش‌بارگذاری صفحات احتمالی

## ۳۱. ماژول AI مکالمه‌ای (Conversational AI Builder) — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** Jotform AI (مارس ۲۰۲۶)، Typeform AI Platform (فوریه ۲۰۲۶)
> این ماژول استاندارد جدید صنعت در ۲۰۲۶ است و باید در فاز ۲ پیاده‌سازی شود.

### ۳۱.۱ ساخت آزمون از طریق مکالمه (Chat-to-Quiz)

کاربر به‌جای کلیک روی دکمه‌ها، با AI **گفتگو** می‌کند و آزمون کامل ساخته می‌شود:

```
کاربر: «یه آزمون ۱۵ سوالی درباره فصل سوم کتاب شیمی دهم بساز،
        سطح متوسط، با تایمر ۳۰ دقیقه و نمره منفی»

AI:    «آزمون ساخته شد. ۱۵ سوال چهارگزینه‌ای، تایمر ۳۰ دقیقه،
        نمره منفی ۰.۲۵. می‌خوای سوالات رو ببینی یا مستقیم منتشر کنی؟»

کاربر: «سوال ۵ رو سخت‌تر کن و یه تصویر بهش اضافه کن»

AI:    «سوال ۵ ویرایش شد. تصویر مرتبط با واکنش اکسیداسیون
        پیشنهاد می‌دم — تأیید می‌کنی؟»
```

### ۳۱.۲ کانال‌های ورودی مکالمه

| کانال | توضیح | اولویت |
|-------|-------|--------|
| متن (Text Chat) | تایپ دستورالعمل | 🔴 ضروری |
| صدا (Voice Input) | گفتن دستورالعمل | 🟡 مهم |
| آپلود فایل در چت | ارسال PDF/Word در مکالمه | 🔴 ضروری |

### ۳۲.۱ AI Response Enrichment (غنی‌سازی پاسخ)

## ۳۳. ماژول گیمیفیکیشن پیشرفته — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** Kahoot Confidence Mode (ژانویه ۲۰۲۶)، Kahoot Q2 2026 Updates
> ویژگی‌های جدید گیمیفیکیشن که در سند اولیه وجود نداشتند.

### ۳۳.۱ Confidence Mode (حالت اطمینان‌سنجی)

یکی از مهم‌ترین نوآوری‌های آموزشی ۲۰۲۶ — اندازه‌گیری **metacognition** (آگاهی از دانش خود):

**نحوه کار:**
```
سوال نمایش داده می‌شود
        ↓
شرکت‌کننده پاسخ انتخاب می‌کند
        ↓
سیستم می‌پرسد: «چقدر مطمئنی؟»
  ○ خیلی مطمئنم  (×۲ امتیاز یا ×۲ کسر)
  ○ نسبتاً مطمئنم (×۱.۵)
  ○ حدس می‌زنم   (×۱)
        ↓
نتیجه محاسبه می‌شود
```

**جدول امتیازدهی Confidence Mode:**

| پاسخ | سطح اطمینان | امتیاز |
|------|------------|--------|
| صحیح | خیلی مطمئن | +۲۰۰۰ |
| صحیح | نسبتاً مطمئن | +۱۵۰۰ |
| صحیح | حدس | +۱۰۰۰ |
| غلط | خیلی مطمئن | -۱۰۰۰ |
| غلط | نسبتاً مطمئن | -۵۰۰ |
| غلط | حدس | ۰ |

**کاربردهای آموزشی:**
- شناسایی دانش‌آموزانی که «می‌دانند که نمی‌دانند» (calibrated)
- شناسایی دانش‌آموزانی که «فکر می‌کنند می‌دانند اما نمی‌دانند» (overconfident)
- گزارش Confidence Map برای مدرس

### ۳۳.۲ حالت‌های بازی جدید (Game Modes)

**Accuracy Mode:**
- سرعت اهمیتی ندارد
- فقط صحت پاسخ امتیاز می‌دهد
- مناسب برای آزمون‌های جدی

**Team Battle Mode (بهبودیافته):**
- تیم‌های ۲ تا ۶ نفره
- امتیاز تیمی + فردی
- چالش‌های ویژه تیمی
- لیدربورد تیمی زنده

**Knowledge Check (بررسی دانش):**
- سوالات پیشرفته‌تر از MCQ ساده
- سوالات چندمرحله‌ای
- مناسب برای ارزیابی عمیق‌تر

**Briefing Mode:**
- ابتدا محتوا نمایش داده می‌شود
- سپس سوال پرسیده می‌شود
- ترکیب آموزش + ارزیابی در یک جلسه

### ۳۳.۳ Q&A تعاملی در آزمون زنده

- شرکت‌کنندگان می‌توانند سوال ارسال کنند
- سایرین می‌توانند سوالات را upvote کنند
- مدرس سوالات پرطرفدار را پاسخ می‌دهد
- آرشیو خودکار سوالات پاسخ‌داده‌شده
- خلاصه Q&A در پایان جلسه

### ۳۳.۴ Streak و Daily Challenge

- **Daily Challenge:** یک آزمون کوتاه روزانه
- **Streak Counter:** روزهای متوالی فعالیت
- **Weekly League:** رقابت هفتگی با جوایز
- **Milestone Rewards:** جوایز برای رسیدن به اهداف
- **Social Sharing:** اشتراک‌گذاری دستاوردها در شبکه‌های اجتماعی

## ۳۴. ماژول یادگیری تطبیقی و Spaced Repetition — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** تحقیقات Spaced Repetition 2026، Quizlet AI، Kahoot Self-Study
> ترکیب LLM با الگوریتم‌های تکرار فاصله‌دار — ۲۰–۴۰٪ بهبود نگهداری دانش.

### ۳۴.۱ Spaced Repetition System (SRS)

**اصل کار:**
سوالاتی که کاربر اشتباه پاسخ داده یا با اطمینان پایین پاسخ داده، در فواصل بهینه دوباره نمایش داده می‌شوند:

```
پاسخ غلط → نمایش مجدد در ۱ روز
پاسخ صحیح با اطمینان پایین → نمایش مجدد در ۳ روز
پاسخ صحیح با اطمینان متوسط → نمایش مجدد در ۷ روز
پاسخ صحیح با اطمینان بالا → نمایش مجدد در ۱۴ روز
تسلط کامل → نمایش مجدد در ۳۰ روز
```

**الگوریتم:** ترکیب SM-2 (SuperMemo) با LLM برای تحلیل معنایی سوالات مشابه

### ۳۴.۲ حالت خودآزمایی هوشمند (Smart Self-Study)

**ویژگی‌ها:**
- **Flashcard Mode:** سوال → پاسخ، با امکان flip
- **Practice Test:** آزمون تمرینی با سوالات ضعیف‌ترین حوزه‌ها
- **Micro Lesson:** درس کوتاه ۵ دقیقه‌ای قبل از سوال
- **Vocabulary Review:** مرور لغات/مفاهیم کلیدی
- **Knowledge Check:** بررسی سریع یادگیری

**مسیر یادگیری شخصی‌سازی‌شده:**
```
کاربر آزمون می‌دهد
        ↓
AI نقاط ضعف را شناسایی می‌کند
        ↓
مسیر مطالعه پیشنهاد می‌دهد:
  ۱. مرور مفهوم X (۵ دقیقه)
  ۲. تمرین ۱۰ سوال از موضوع X
  ۳. آزمون کوتاه برای تأیید یادگیری
        ↓
پیشرفت ردیابی می‌شود
```

### ۳۴.۳ Knowledge Map (نقشه دانش)

نمایش بصری از وضعیت یادگیری کاربر:

```
فیزیک دهم
├── مکانیک          ████████░░ ۸۰٪ ✅
│   ├── حرکت یکنواخت ██████████ ۱۰۰٪ ✅
│   ├── شتاب         ████████░░ ۸۰٪ ✅
│   └── نیرو         ██████░░░░ ۶۰٪ ⚠️
├── الکتریسیته      ████░░░░░░ ۴۰٪ ❌
│   ├── بار الکتریکی ██████░░░░ ۶۰٪ ⚠️
│   └── مدار         ██░░░░░░░░ ۲۰٪ ❌
└── نور              ██████████ ۱۰۰٪ ✅
```

**ویژگی‌های Knowledge Map:**
- رنگ‌بندی بر اساس سطح تسلط
- پیشنهاد اولویت مطالعه
- مقایسه با میانگین کلاس
- تاریخچه پیشرفت در طول زمان
- قابل مشاهده توسط مدرس (برای کل کلاس)

### ۳۴.۴ یادآوری هوشمند (Smart Reminders)

- یادآوری بر اساس زمان بهینه مطالعه هر کاربر
- یادآوری قبل از آزمون مهم
- یادآوری برای سوالاتی که زمان مرور آن‌ها رسیده
- ارسال از طریق: پوش نوتیفیکیشن، پیامک، تلگرام، ایمیل
- قابل تنظیم توسط کاربر (ساعت، کانال، فرکانس)

## ۳۶. ماژول ارزیابی صوتی (Voice Assessment) — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** تحقیق arxiv مارس ۲۰۲۶ — آزمون شفاهی با هزینه $0.42/دانش‌آموز
> مناسب برای آزمون‌های زبان، مصاحبه، و ارزیابی مهارت‌های نرم.

### ۳۶.۱ انواع ارزیابی صوتی

**۱. پاسخ صوتی به سوال متنی:**
- سوال به‌صورت متن نمایش داده می‌شود
- شرکت‌کننده پاسخ را با صدا می‌دهد
- AI پاسخ را تبدیل به متن می‌کند (Speech-to-Text)
- AI پاسخ را ارزیابی می‌کند

**۲. آزمون شفاهی کامل (Oral Exam):**
- AI سوال را با صدا می‌پرسد (Text-to-Speech فارسی)
- شرکت‌کننده پاسخ می‌دهد
- AI پاسخ را تحلیل می‌کند
- گفتگوی چندمرحله‌ای (Follow-up Questions)

**۳. ارزیابی تلفظ (Pronunciation Assessment):**
- مناسب برای آزمون‌های زبان
- تحلیل تلفظ، لحن، روانی گفتار
- امتیازدهی بر اساس معیارهای استاندارد

### ۳۶.۲ قابلیت‌های Speech-to-Text فارسی

- تبدیل گفتار فارسی به متن با دقت بالا
- پشتیبانی از لهجه‌های مختلف فارسی
- تشخیص اعداد فارسی و انگلیسی
- تشخیص اصطلاحات تخصصی (قابل آموزش)
- کار در محیط‌های پرسروصدا

### ۳۶.۳ ارزیابی پاسخ صوتی با AI

**معیارهای ارزیابی:**
- **محتوا:** آیا پاسخ صحیح است؟
- **کامل بودن:** آیا همه جنبه‌ها پوشش داده شده؟
- **دقت:** آیا اطلاعات دقیق است؟
- **روانی:** (برای آزمون زبان) سرعت و روانی گفتار
- **تلفظ:** (برای آزمون زبان) صحت تلفظ

**خروجی ارزیابی:**
- نمره عددی
- بازخورد متنی
- نقاط قوت و ضعف
- پیشنهاد بهبود

### ۳۶.۴ Text-to-Speech فارسی

- تبدیل متن سوال به صدای فارسی طبیعی
- چند صدای مختلف (مرد/زن، لحن رسمی/غیررسمی)
- تنظیم سرعت و لحن
- مناسب برای دانش‌آموزان کم‌بینا

|--------|-------|
| آزمون زبان انگلیسی | Speaking test خودکار |
| آزمون زبان فارسی | ارزیابی روانی خواندن |

## ۳۷. ماژول گواهینامه بلاکچین — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** W3C Verifiable Credentials، بازار $1.13B در ۲۰۲۶، everycred.com
> کارفرماها در ۲۰۲۶ گواهینامه‌های blockchain-verified را ترجیح می‌دهند.

### ۳۷.۱ گواهینامه قابل تأیید (Verifiable Credential)

**استانداردهای پشتیبانی‌شده:**
- **W3C Verifiable Credentials (VC):** استاندارد جهانی
- **Decentralized Identifiers (DID):** هویت غیرمتمرکز
- **Open Badges 3.0:** استاندارد badge دیجیتال
- **Blockcerts:** استاندارد گواهینامه بلاکچین

**ساختار گواهینامه:**
```json
{
  "@context": ["https://www.w3.org/2018/credentials/v1"],
  "type": ["VerifiableCredential", "ExamCertificate"],
  "issuer": "did:web:platform.ir",
  "issuanceDate": "1404-01-15",
  "credentialSubject": {
    "id": "did:web:user.ir",
    "name": "علی رضایی",
    "exam": "آزمون پایان ترم شیمی",
    "score": 87,
    "grade": "عالی",
    "issuer": "آموزشگاه نمونه"
  },
  "proof": {
    "type": "Ed25519Signature2020",
    "verificationMethod": "..."
  }
}
```

### ۳۷.۲ تأیید اعتبار فوری

**روش‌های تأیید:**
- **QR Code:** اسکن و تأیید فوری
- **لینک عمومی:** بدون نیاز به ورود
- **API:** تأیید برنامه‌نویسی برای کارفرماها
- **LinkedIn:** اشتراک‌گذاری مستقیم با تأیید خودکار
- **Email Verification:** ارسال درخواست تأیید به صادرکننده

**صفحه تأیید عمومی نمایش می‌دهد:**
- نام دارنده گواهینامه
- نام آزمون و صادرکننده
- تاریخ صدور و انقضا
- نمره (اختیاری)
- وضعیت: معتبر / منقضی / ابطال‌شده
- امضای دیجیتال تأییدشده

### ۳۷.۳ Micro-credentials و Badge Stack

**Micro-credential:**
- گواهینامه برای مهارت‌های کوچک‌تر
- قابل ترکیب برای ساخت گواهینامه بزرگ‌تر
- مثال: ۵ micro-credential ریاضی = گواهینامه ریاضی پیشرفته

**Badge Stack:**
```
🏆 گواهینامه برنامه‌نویسی Python
├── 🥇 Python پایه (۸۵٪)
├── 🥇 Python پیشرفته (۹۰٪)
├── 🥈 کار با دیتابیس (۷۸٪)
└── 🥇 پروژه عملی (۹۲٪)
```

### ۳۷.۴ کیف پول دیجیتال (Digital Wallet)

- پروفایل عمومی کاربر با همه گواهینامه‌ها
- قابل اشتراک‌گذاری به‌عنوان رزومه دیجیتال
- مرتب‌سازی بر اساس موضوع، تاریخ، صادرکننده
- دانلود همه گواهینامه‌ها به‌صورت یکجا
- لینک اختصاصی: `platform.ir/portfolio/username`

### ۳۷.۵ محدودیت‌های Blockchain Certificate

| پلن | گواهینامه VC | Badge Stack | Digital Wallet |
|-----|------------|------------|---------------|
| رایگان | ❌ | ❌ | ✅ (ساده) |
| پایه | ✅ | ❌ | ✅ |
| حرفه‌ای | ✅ | ✅ | ✅ کامل |
| سازمانی | ✅ + Custom DID | ✅ | ✅ White-label |

## ۳۸. ماژول AI Explainability و Bias Monitoring — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** AI Quiz Trends 2026 (upscend.com)، EU AI Act (اجرا از آگوست ۲۰۲۶)
> کاربران ۲۰۲۶ انتظار دارند AI توضیح دهد چرا این سوال را تولید کرده.

### ۳۸.۱ AI Explainability (توضیح‌پذیری هوش مصنوعی)

**برای هر سوال تولیدشده توسط AI:**

```
سوال: «کدام گزینه فرمول شیمیایی آب را نشان می‌دهد؟»

[🔍 چرا این سوال؟]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
منبع: صفحه ۴۵ کتاب شیمی دهم، فصل ۲
موضوع: فرمول‌های شیمیایی پایه
سطح دشواری: آسان (۹۲٪ پاسخ صحیح در آزمون‌های مشابه)
هدف یادگیری: آشنایی با فرمول‌های پایه
پیشنهاد: مناسب برای شروع آزمون
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**اطلاعات Explainability برای هر سوال:**
- منبع محتوا (صفحه، فصل، بخش)
- هدف یادگیری مرتبط
- سطح دشواری تخمینی با دلیل
- آمار عملکرد سوالات مشابه
- پیشنهاد جایگاه در آزمون (ابتدا/وسط/انتها)
- هشدار در صورت ابهام یا مشکل احتمالی

### ۳۸.۲ Bias Detection (تشخیص تعصب)

AI سوالات را از نظر تعصب بررسی می‌کند:

**انواع تعصب قابل تشخیص:**

| نوع تعصب | مثال | اقدام |
|----------|------|-------|
| جنسیتی | فرض مرد بودن مهندس | هشدار + پیشنهاد اصلاح |
| فرهنگی | اشاره به فرهنگ خاص | هشدار |
| اقتصادی | فرض دسترسی به امکانات خاص | هشدار |
| زبانی | واژگان پیچیده غیرضروری | پیشنهاد ساده‌سازی |
| منطقه‌ای | اشاره به مکان خاص | هشدار |

**گزارش Bias برای کل آزمون:**
- درصد سوالات با هشدار تعصب
- نوع تعصب‌های شناسایی‌شده
- پیشنهاد اصلاح برای هر سوال
- امتیاز کلی «انصاف آزمون» (Fairness Score)

### ۳۸.۳ Quality Score (امتیاز کیفیت سوال)

هر سوال تولیدشده توسط AI یک امتیاز کیفیت دریافت می‌کند:

```
سوال: «پایتخت ایران کجاست؟»

امتیاز کیفیت: ۶۵/۱۰۰ ⚠️
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ وضوح سوال: ۹۰/۱۰۰
✅ صحت پاسخ: ۱۰۰/۱۰۰
⚠️ تمایز گزینه‌ها: ۶۰/۱۰۰ (گزینه‌ها خیلی واضح هستند)
❌ سطح دشواری: ۳۰/۱۰۰ (خیلی آسان برای دانشجو)
⚠️ ارتباط با موضوع: ۷۰/۱۰۰

پیشنهاد: این سوال برای آزمون دانشجویی خیلی ساده است.
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

### ۳۸.۴ Continuous Monitoring (پایش مستمر)

**پس از برگزاری آزمون:**
- مقایسه عملکرد واقعی با پیش‌بینی AI
- شناسایی سوالاتی که AI اشتباه ارزیابی کرده
- بهبود مدل بر اساس داده‌های واقعی
- گزارش دقت AI به مدرس

**داشبورد AI Health:**
- دقت پیش‌بینی سطح دشواری: X٪
- نرخ سوالات با کیفیت پایین: X٪
- تعداد هشدارهای Bias این ماه
- بهبود مدل در طول زمان

### ۳۸.۵ انطباق با EU AI Act

از آگوست ۲۰۲۶ EU AI Act کاملاً اجرایی می‌شود:
- مستندسازی تصمیمات AI
- حق اعتراض به تصمیمات AI
- شفافیت در استفاده از AI
- ممنوعیت AI برای ارزیابی‌های پرخطر بدون نظارت انسانی
- گزارش‌دهی دوره‌ای به کاربران

## ۳۹. ماژول Agentic AI — به‌روزرسانی آوریل ۲۰۲۶

> **منبع:** No-Code and Agentic AI for Training 2026 (elearningindustry.com)
> ۴۰٪ اپلیکیشن‌های سازمانی تا پایان ۲۰۲۶ AI Agent خواهند داشت.

### ۳۹.۱ تعریف Agentic AI در پلتفرم

برخلاف AI معمولی که فقط به دستور پاسخ می‌دهد، **Agentic AI** به‌صورت خودمختار اهداف را دنبال می‌کند:

```
هدف: «مطمئن شو همه دانش‌آموزان کلاس الف
      تا پایان هفته آزمون فصل ۳ را بدهند»

Agent اقدامات زیر را خودکار انجام می‌دهد:
  ۱. بررسی وضعیت هر دانش‌آموز
  ۲. ارسال یادآوری به کسانی که شرکت نکرده‌اند
  ۳. ارسال یادآوری دوم ۲۴ ساعت بعد
  ۴. اطلاع به مدرس اگر کسی هنوز شرکت نکرده
  ۵. گزارش نهایی پس از پایان مهلت
```

### ۳۹.۲ Agent‌های از پیش تعریف‌شده

**Agent ۱: مدیر آزمون (Exam Manager)**
- پیگیری شرکت‌کنندگان
- ارسال یادآوری خودکار
- تمدید مهلت در صورت نیاز
- گزارش وضعیت به مدرس

**Agent ۲: مربی یادگیری (Learning Coach)**
- شناسایی دانش‌آموزان در معرض خطر
- پیشنهاد منابع مطالعاتی
- تنظیم مسیر یادگیری شخصی
- ارسال تشویق و انگیزه

**Agent ۳: تحلیلگر عملکرد (Performance Analyst)**
- تحلیل خودکار نتایج آزمون
- شناسایی الگوهای ضعف در کلاس
- پیشنهاد تغییر در برنامه درسی
- گزارش هفتگی به مدرس

**Agent ۴: دستیار محتوا (Content Assistant)**
- پیشنهاد سوالات جدید بر اساس ضعف‌های شناسایی‌شده
- به‌روزرسانی بانک سوال
- بررسی کیفیت سوالات موجود
- پیشنهاد حذف سوالات ضعیف

### ۳۹.۳ ساخت Agent سفارشی (No-Code)

مدرس می‌تواند Agent اختصاصی بسازد:

```
نام Agent: «یادآور کنکور»

هدف: آماده‌سازی دانش‌آموزان برای کنکور

قوانین:
  اگر [دانش‌آموز ۳ روز آزمون نداده]
  → [ارسال پیامک یادآوری]

  اگر [نمره آزمون < ۵۰٪]
  → [ارسال لینک منابع مطالعاتی]
  → [اطلاع به والدین]

  اگر [۱ هفته به آزمون مهم مانده]
  → [ارسال برنامه مطالعاتی]
  → [فعال کردن آزمون‌های تمرینی روزانه]

زمان‌بندی: بررسی هر ۶ ساعت
```

### ۳۹.۴ Multi-Agent Collaboration

در سازمان‌های بزرگ، چند Agent با هم کار می‌کنند:

```
Agent مدیریت آزمون
        ↓ (نتایج آزمون)
Agent تحلیل عملکرد
        ↓ (شناسایی ضعف‌ها)
Agent مربی یادگیری
        ↓ (مسیر یادگیری)
Agent محتوا
        ↓ (سوالات تمرینی)
Agent مدیریت آزمون (چرخه بعدی)
```

### ۳۹.۵ محدودیت‌های Agentic AI

| پلن | Agent پیش‌فرض | Agent سفارشی | Multi-Agent |
|-----|-------------|-------------|------------|
| رایگان | ❌ | ❌ | ❌ |
| پایه | ۱ Agent | ❌ | ❌ |
| حرفه‌ای | همه | ۳ Agent | ❌ |
| سازمانی | همه | نامحدود | ✅ |

### ۳۹.۶ کنترل و نظارت بر Agent

- لاگ کامل همه اقدامات Agent
- امکان توقف Agent در هر لحظه
- تأیید دستی برای اقدامات حساس
- محدودیت دامنه عملکرد Agent
- هشدار برای اقدامات غیرمعمول

سند نیازمندی‌های نسخه ۱.۰ پایه‌های محکمی داشت و اکثر ویژگی‌های اصلی را پوشش می‌داد. با این حال، تحقیق آوریل ۲۰۲۶ نشان داد که **۳ شکاف بحرانی** وجود داشت:

1. **Conversational AI Builder** — Jotform در مارس ۲۰۲۶ این را به استاندارد صنعت تبدیل کرد
2. **AI Workflow Automation** — Typeform در فوریه ۲۰۲۶ این را معرفی کرد
3. **Confidence Mode** — Kahoot در ژانویه ۲۰۲۶ این را اضافه کرد

این ۳ ویژگی باید در **فاز ۲** پیاده‌سازی شوند تا پلتفرم با استانداردهای ۲۰۲۶ رقابت‌پذیر باشد.
